# 数据源实测（第四轮第 0 步，2026-10-26 至 10-27）

脚本 `tools/probe.py`，工作流 `.github/workflows/probe.yml`（推送 radar 时跑；日志只打状态码、条数和耗时，明细在构件里）。
测了三处：用户 Mac（经本机代理）、GitHub Actions（美国，2026-10-26 18:32 UTC 起，先每个源取一次，再每 5 分钟一轮共 18 轮）、Cloudflare Worker（**还没测**：要用户注册 Cloudflare，见文末）。
robots.txt 按 RFC 9309 判断（空行不分组、最长匹配）；Python 自带的解析器会把 `User-agent: *` 后面带空行的写法读成"全部允许"，第一次实测因此把 Lipper 的 `/feed/` 误判成允许，已改。

三关（原则 8）：**稳**＝ Actions 上能取到、返回正常内容；**登**＝有日期或时间戳，能按"能看到的时间"截断、能登记能检验；**页**＝每天能变出一个读数或一条消息。

## 其他

- **页面加密包**：GitHub Pages 上现在是 404（见下），所以在本机用 10-23 的数据和临时密码生成：0.93 MB（934,366 字节）。第 2 步首屏不超过它的 1.5 倍（1.40 MB）。data 分支的 `data.enc` 约 0.30 MB。
- **Cloudflare 免费额度**（10-26 查文档）：每天 10 万次请求；每次运行 CPU 10 毫秒；一个账号 5 个定时；每次 50 个子请求（D1、KV 也算）、同时 6 个连接。D1：每天写 10 万行、读 500 万行、存 5 GB；**写入时每个带了被写列的索引多算 1 行**。
- **现在的面板有两个问题**（main 分支，这一轮没改）：
  1. GitHub 上没有 `PAGE_PASSWORD` 这个 Secret，所以从 10-23 起一直没生成网页，Pages 打开是 404。
  2. 定时实际几个小时才跑一次（10-24 到 10-26 的运行间隔 2–6 小时）：`run.yml` 的接力判断"上一次定时触发"时，查到的就是这次运行自己，于是总以为"定时在正常触发"，从来不接力。改法：查 `event=schedule` 时排除当前运行（或取第二条）。
  这两个要改 main，等用户同意。

## 要用户做的（Cloudflare）

1. 打开 https://dash.cloudflare.com/sign-up 用邮箱注册（免费版）。
2. 右上角头像 → My Profile → API Tokens → Create Token → Create Custom Token：权限加两行 Account · Workers Scripts · Edit 和 Account · D1 · Edit，Account Resources 选你的账号 → Continue → Create Token，复制令牌（只显示一次）。
3. 账号首页右侧（或 Workers 页面右侧）复制 Account ID。
4. GitHub 网页：parker123450/sentiment-monitor → Settings → Secrets and variables → Actions → New repository secret，加两个：`CLOUDFLARE_API_TOKEN`（第 2 步的令牌）、`CLOUDFLARE_ACCOUNT_ID`（第 3 步的 ID）。
